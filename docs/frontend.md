# Frontend

H SPACE Studio is an orange, charcoal and warm-white interface inspired by the owner's H SPACE logo. The owner requested a strong background on both sign-in and interior pages, then specified a Toyota Camry. The resulting local AI-generated scene combines a graphite Camry, architectural orange lighting and a curved orange road.

The full-scene sign-in background is mirrored through CSS so the car sits beside the story and the form occupies calmer space. A dense form surface preserves readability; light mode uses a white form over the same cinematic scene. Inside the application, the scene is used in the vehicle-list hero and beneath a much quieter page scrim. It is decorative and never used as an inventory/card photo.

The frontend remains plain Jinja2/HTML/CSS/JavaScript without npm, a bundler, external fonts or a new runtime dependency. The background is hspace-camry-studio.png (1672 × 941, about 1.7 MiB); it is preloaded only on sign-in and reused through the browser cache. No full-screen video, particles or parallax are needed.

Shared _header.html, _icons.html and _brand.html supply consistent navigation and controls. Signed-in pages expose Vehicles and, for the owner only, Team. Arabic/RTL and light/dark preferences apply before paint through appearance.js. Login and vehicle pages manage their own translated interactions; page-tools.js supplies language/theme controls for Team and Office previews. Preferences contain presentation settings only.

The sign-in form supports password-manager autocomplete, paste, and an accessible Show/Hide password button. Account registration is still unavailable. Team cards show real identity, role and status, retain the protected admin behavior and allow retry after a load error. Language switching updates rendered cards and feedback.

Vehicle cards retain independent cover upload/removal. Detail forms keep only the agreed fields. Image/document deletion still requires confirmation and CSRF; gallery deletion never changes the cover. File actions wrap on narrow screens and use at least 44px targets. Preview/download routes and backend behavior are unchanged.

CSS uses semantic colors, logical properties, responsive grids, reserved image aspect ratios, visible focus and reduced-motion support. The vehicle grid uses five columns from 1200 CSS pixels, four from 1024, three from 800, two from 561 and one below that. Header/login breakpoints also adapt at 560, 800 and 1150px. Cards use compact padding while retaining 44px action targets. Wide and narrow native Chrome windows were reviewed; exact review sizes and physical devices remain unverified.

The reviewed design rules and tokens are in [the design master](../design-system/h-space/MASTER.md). ui-ux-pro-max supplied general accessibility/interaction guidance; its automated style suggestions did not provide a complete brand-matching result, so unrelated palettes, academic typography and marketing-storytelling layouts were rejected.

The frontend-design pass adds interactions.js: delegated fine-pointer card tilt/highlight with one frame at a time, stable action-button targets, native touch/keyboard behavior, and resets on pointer leave, scroll, resize, hidden state and card rerender. It honors live reduced-motion changes. Details/dialogs have brief open transitions; sign-in has one entrance. Busy saves have a spinner and aria-busy. Section icons replace non-sequential numbers.

Initial Studio validation: 54 existing tests, all page templates and six JavaScript syntax checks passed. Calculated foreground/background token contrasts exceeded 4.5:1 for the checked text pairs and 3:1 for input boundaries. The real loopback server returned 200 for the new login, Camry asset and shared controls. These checks are not rendered-layout or full accessibility certification. Browser access was unavailable during the initial Studio pass. The subsequent interaction pass passed 14 focused HTTP tests, seven syntax checks and isolated controller checks. Native Windows Chrome review now covered wide/narrow windows and both languages/themes with the existing vehicle. Computer Use then stopped because it could not establish the browser URL reliably; the last mobile-heading change was not visually rechecked. A full five-occupied-card row, pointer appearance, precise viewport widths and physical devices still need review. See [README](../README.md).
